# ナレッジベース v0.1.0

ディレクトリ構成は docs/03-database.md「ナレッジベースとルールの保存」を参照してください。すべてのファイルの SHA-256 は manifest.json に記録します。manifest.json は `pnpm kb:manifest` で生成し、`pnpm kb:check` で検証します。各サービスは起動時に `@ijime/kb-loader` で検証します。

## レビュー状況

このバージョンは **DRAFT / 専門家未レビュー** です。`manifest.reviewStatus` は `draft_pending_expert_review` で、`manifest.approvedBy` は空の配列のままにしておく必要があります。`releasedAt` はバージョンファイルの作成時刻であり、リリース済み・臨床的に検証済み・承認済みであることを示すものではありません。

6つのキャラクター、3つの学年帯、11本の会話ガイドは、PRD、Agent アーキテクチャ、まもりの憲章をもとに書いています。出典は `content-review.yaml` に登録しています。日本語の例文はすべて開発用に創作したもので、子どもの実際の記録でも、専門家の意見でも、有効性の根拠でもありません。医療上の助言、診断、シグナルのラベル、リスクのしきい値、専門家の署名は含みません。

これらの内容は、隔離されたローカル開発と構造のテストに使えます。専門家レビュー、日本の子どもにとっての言葉のわかりやすさのテスト、実際のモデルでの評価はまだ終わっていません。決定論的な検証はこれらの代わりにはなりません。そのほかのシグナル、テンプレート、ルールについても、専門家レビューは終わっていません。

## 検証とリリース

- `pnpm kb:manifest`：ハッシュを更新し、レビュー状況はそのまま保ちます。書き込む前に、会話コンテンツの一覧、すべてのキャラクターと学年帯、出典、必須の章を検証します。内容が基準を満たさないときは、新しい manifest を書き込みません。
- `pnpm kb:check`：上記の構造とハッシュを検証します。本番リリースを許可するものではありません。
- `node packages/kb-loader/dist/cli.js kb/v0.1.0 --check --release`：リリース状態を追加で確認します。現在のドラフトでは失敗するのが正しく、ファイルは変更しません。このコマンドはデプロイのパイプラインには組み込まれていません。
- `pnpm --filter @ijime/kb-loader test`：構造、出典、不正な例、リリース拒否のテストです。pet-agent の `content.test.ts` は、実際のファイルの組み立てとローカルの Skill 検索を確認します。

`createSkillSearch` は、本番モードでは未承認の Skill に対して空の結果を返し、設定済みのクラウドのコーパスにも問い合わせません。これは Skill 検索の境界であり、すべてのサービスの起動時に働く共通のリリースゲートではありません。デプロイする側は、別途リリース検証を実行する必要があります。

## 低学年のシグナル

A 領域のモデルシグナルは、文部科学省の調査にあるいじめの8つの態様それぞれに1つずつあり、`A-EXCL-003` を含めて low の例文があります（`signals/README.md` を参照）。これらの定義と例文は **ドラフト** です。例文は開発用に創作したもので、低学年の子どもが本当にこのように話すのか、シグナル抽出器が低学年のサンプルでどう動くのかは、まだ検証していません。専門家が最終レビューで署名するまでは、低学年の検知が完成したとは言えません。危機検知は独立した処理であり、この危機以外の部分の不足には含まれません。

シークレットキャラクターの人格には、安定して使える既定の内容を用意しています。現在の Agent の入力にはバリアント ID がないため、シークレットキャラクターのバリアントのランダム生成と保存は実装していません。

## 出典の登録（sources/registry.yaml）

シグナル、語彙表、ルール、背景データの出典は、すべて `sources/registry.yaml` に登録します。フィールドは `id`、`title`、`publisher`、`url`、`year`、`accessed_on`、`license`、`strength`（high/medium/low）、`verified`、`notes` です。シグナルの `evidence.sources` は、ここにある id だけを参照できます。`kb:check` は、未登録の id、重複した id、自由記述の `evidence.source` を使っているシグナルをエラーにします。

登録済みの外部の出典（文部科学省の調査、国立教育政策研究所の追跡調査、いじめ防止対策推進法、基本的な方針、こども基本法、個人情報保護法、内閣府の祝日、PRD が引用する4本の論文、都道府県チェックリストの仮登録）は、すべて `verified: false` です。URL には確実にわかっている公式ドメインか PRD が引用しているリンクだけを書いており、年、具体的なページ、ライセンスはまだ人が開いて確認していません。1件を確認する手順は次のとおりです。URL を開いて文書が存在し、title と一致することを確かめます。`year`、`accessed_on`、具体的なページの URL、`license` を補います。`verified` を true にします。確認者をコミットメッセージに書きます。`prefectural_checklists` は仮登録です。実際に参照するチェックリストを1件ずつ登録したうえで、仮登録を削除します。内部ドキュメント（`doc_prd`、`doc_agent_architecture`、`doc_backend_workers`）の `verified: true` は、ファイルがリポジトリにあることを示すだけで、外部のエビデンスではありません。これらを参照するルールシグナルには、外部の出典を追加する必要があります。

## ナレッジベースの内容の検証（validateKnowledgeBase）

`pnpm kb:manifest` と `pnpm kb:check` は、ハッシュの検証のあとに `validateKnowledgeBase` を実行します。失敗したときは manifest を書き込みません。

- シグナル：出典の id が解決できること。古いフィールド `evidence.source` には書き換えを促すエラーを出します。`explicit: true` かつ `method: model` のシグナルは、`grade_bands` の学年帯ごとに例文が1つ以上必要です（`examples_ja` は学年帯ごとに分けて書きます。形式は `signals/README.md` を参照）。宣言していない学年帯を含めることはできません。signal_id は重複できません。
- 語彙表：分類ごとに `explicit` と `grade_bands` が必要です。すべての表現を NFKC 正規化（trim を含む）したうえで、ファイル全体で重複を調べます。重複があれば失敗します。
- 相談窓口：`resources` と `candidates` の各項目に、`official_url`、`verified_at`（日付または null）、`verified_by`（未定でも可）が必要です。id は重複できません。電話番号か URL のどちらかが必要です。`verified_at: null` でも `kb:check` は通りますが、未確認であることを表します。
- 祝日と学期カレンダーが参照する `source_ids` は、registry に登録されている必要があります。

## 語彙表（lexicon/ja.yaml）

14分類あります。話題回避、仲間はずれ・無視、冷やかし・悪口、暴力、恐喝、金品隠し・破壊、強要、ネット誹謗中傷、登校回避、自己否定、絶対化、身体化、ネット用語、危機です。分類ごとに `explicit` と `grade_bands` を付けています。

`crisis` の分類だけが `packages/crisis-detector` のキーワード層に入ります。一致したものはすべて危機として扱うため、ここには完全な表現だけを置き、「切りたい」「OD」「自殺」のように「髪切りたい」「自殺のニュース」にも一致する短い語は置きません。暴力・恐喝の分類の表現はキーワード層に入れません。現在進行中の暴力や恐喝が L4 に当たるかどうかは、モデルによるスクリーニングと再確認で判断します。`crisis` の分類に追加や削除をしたときは、危機検知のテストと評価セットも合わせて更新してください。

## 背景データ（resources/）

- `jp_holidays.yaml`：2028 年末までを収録しています。春分の日・秋分の日は前年 2 月の官報で公示されるため、それまでは天文推算値を使い、`estimated: true` を付けます。公示後に照合して、この印を外します。出典は `cao_national_holidays` で、人による確認はまだです。
- `school_calendars.yaml`：東京都、大阪府、北海道の 2026 年度の仮データです。日付は一般的な慣例に基づく例示で、すべて `verified: false` です。保守の手順はファイルの先頭に書いています。現時点でこのファイルを読むコードはありません。
- `hotlines.yaml`：`resources` は、API（`GET /v1/child/help-resources`）と危機時の定型文が返す4件です。`candidates` は確認待ちの候補（子どもの人権110番、こころの健康相談統一ダイヤル、よりそいホットライン、文科省/こども家庭庁 SNS相談）で、API は返しません。

相談窓口の確認手順（人による作業が必要です）：

1. `official_url` を開き、運営主体、番号、受付時間、対象年齢がファイルと一致することを確かめます。`official_url` を具体的なページに書き換えます。
2. 受付時間内に実際に1回電話をかけ（または公式の手段で確認し）、つながるかどうか、子どもが直接かけるのに適しているかどうかを記録します。
3. `verified_at`（YYYY-MM-DD）と `verified_by`（確認者の氏名または役割）を記入し、`notes` に確認方法を書きます。
4. 候補の項目は、1〜3 を終えてから `resources` に移します。移すと API が返す順序と件数が変わるため、`services/api/src/app.test.ts` と `packages/kb-loader/test/real-kb.test.ts` のアサーションも合わせて更新し、表示順はプロダクト責任者が確認します。
5. 半年ごと、またはいずれかの機関が変更を告知したときに、1〜3 をやり直します。本番公開の前に、すべての `resources` の `verified_at` が null でない状態にします。
